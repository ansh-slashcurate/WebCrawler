A crawler that knows when to stop reading.

rag_crawler is a Scrapy spider that turns a list of seed URLs into a clean, RAG-ready corpus. Point it at a whole site for full coverage, or hand it an entity and it prunes itself down to only the pages that mention it — logging into gated sites, riding out bot walls, and keeping every crawl's output separate from the last.

Scrapy 2.18 scrapy-redis (frontier) scrapy-playwright (JS + auth) trafilatura (extraction) Redis
01 · Orientation

What this is, and isn't

Give it seed.txt and it link-follows outward (plus sitemap discovery) up to max_depth, fetching plain HTTP first and escalating to a real Playwright browser only when a page turns out to need JS or is behind a login. Every page passes through four ordered pipeline stages — dedup, extraction, relevance, storage — before it reaches disk as a line in clean.jsonl.

It does not solve CAPTCHAs, bypass paywalls, or defeat 2FA. Authentication support (below) is for sites you already have legitimate access to; bot-wall handling (below) detects and logs what it can't get past rather than trying to force it.

02 · How a page moves through it

Architecture

One request's path from the frontier to clean.jsonl — and the three places along the way it can get dropped instead.

The four pipeline stages

100 · ContentDedupPipeline

Content dedup

SHA-256 of the raw HTML, atomically SADD'd into a Redis set scoped to this entity+run. Two workers hashing the same page at once still only let one through.

drops on: exact duplicate content
150 · NormalizationPipeline

Extraction

trafilatura (favor_recall=True) pulls prose out of the HTML; tables are extracted separately as row dicts so they never get flattened into text.

drops on: no content and no tables
175 · EntityRelevancePipeline

Relevance gate

A no-op unless the crawl was started with -a entity=. Re-scores cleaned_content against the entity query — the actual gate on what reaches storage.

drops on: entity not mentioned
200 · StoragePipeline

Storage

Appends to pages.jsonl and clean.jsonl under this run's output folder, then re-counts both files on close to catch silent data loss.

writes: pages.jsonl, clean.jsonl
03 · First crawl

Quickstart

Redis and a Chromium install are the only two things this needs beyond the Python deps.

cd crawler
pip install scrapy scrapy-redis scrapy-playwright trafilatura pypdf redis lxml
playwright install chromium

# start Redis (already running on localhost:6379 assumed by settings.py)
redis-server &

# one URL per line
echo "https://example.com/" > seed.txt

scrapy crawl rag_crawler

Output lands in output/<run_id>/ (no entity given → no entity-slug folder). Every run gets its own folder — see Output structure.

04 · Focused crawling

Entity-focused crawling

Hand it a name and the crawl stops behaving like a full-site archiver and starts behaving like a search: it still walks the site, but only keeps — and only keeps following — the parts that are actually about the entity. 

# name only
scrapy crawl rag_crawler -a entity="Shashi"

# name + aliases + disambiguating context (all optional, independent)
scrapy crawl rag_crawler \
  -a entity="John Smith" \
  -a aliases="J. Smith,Johnny Smith" \
  -a context="CFO,Acme Corp"

The matching rule

Word-boundary, case-insensitive regex — no embeddings, no LLM call per page. A page is relevant if it mentions the name or an alias, and (only if context terms were given) at least one context term. Context is what tells your John Smith apart from every other one on the site. Score = name_hits×2 + context_hits, used to prioritize which link gets fetched next.

How the frontier prunes itself

Each request carries an irrelevant_streak forward through its meta. A relevant page resets it to 0; an irrelevant one increments it. Once a branch hits max_irrelevant_streak (default 2) with no hit, the spider stops following links from it — even if max_depth hasn't been reached yet. Anchor text that already mentions the entity gets a higher Request(priority=…), so promising links are dequeued before filler pages.

Per-entity isolation

output/, the content-dedup set, and the URL dupefilter are all scoped by slugify(entity), so crawling "Shashi" and "Neeraj" against the same seed.txt never mix corpora or wrongly dedupe one entity's page against another's.

05 · Gated content

Authentication

For sites you already have legitimate access to — your own subscription, an internal tool, an authorized engagement. Not a CAPTCHA or paywall bypass: a login that needs a second factor will simply time out and get logged as a failed login.

storage_state

Reuse a session

Loads cookies + localStorage exported from a real browser (or a prior playwright_login run) into a named Playwright context. No login flow runs at all.

form_login

Plain HTML form

Two-hop GET+POST via FormRequest.from_response(). Scrapy's cookie jar carries the resulting session through every later request — no Playwright needed.

playwright_login

JS-rendered login

Fills fields and clicks submit in a real browser, waits for a success selector. Can save storage_state afterward so future runs skip straight to method 1.

api_token

Token / API key

A downloader middleware injects a header (Authorization, X-API-Key, …) on every request to the domain. No login step at all.

auth.json

One entry per domain from seed.txt, in crawler/auth.json (gitignored — copy it from auth.example.json). It only ever references environment variable names, never the credentials themselves: 

{
  "app.example.com": {
    "method": "playwright_login",
    "login_url": "https://app.example.com/login",
    "username_selector": "#email",
    "password_selector": "#password",
    "submit_selector": "button[type=submit]",
    "success_selector": ".dashboard-home",
    "username_env": "APP_USERNAME",
    "password_env": "APP_PASSWORD",
    "save_storage_state": "auth/app.example.com.json"
  }
}

Missing env var, missing storage_state file, or an unknown method all raise AuthError at spider startup — before a single request goes out, not mid-crawl on the first page that needed it.

06 · Bot walls

Bot-challenge handling

crawler/challenge.py matches response status and body against known interstitial markers before anything else touches the page — so a Cloudflare "checking your browser" screen never gets mistaken for real content.

SignalMatches
status403, 429, 503 (also whitelisted via HTTPERROR_ALLOWED_CODES so they reach parse() at all)
Cloudflare"checking your browser", "just a moment", cf-browser-verification, cf_chl_opt, cf-turnstile
CAPTCHAg-recaptcha, hcaptcha.com, "verify you are human", GeeTest
Bot-mitigationcaptcha-delivery.com (DataDome), px-captcha (PerimeterX)

One retry, then stop

First hit → one retry via Playwright with a 5s extra wait, which resolves the auto-passing JS-only kind (no human action needed, just time). Still challenged after that → logged to blocked.jsonl and the spider moves on. No infinite retries, no content stored, no link-following into the walled-off page.

07 · Where things land

Output structure

Every crawl invocation gets its own folder — a crash that leaves the Redis frontier non-empty resumes into the same one; anything else gets a new run_id (YYYYMMDD_HHMMSS_PID), so old retrieved content is never overwritten. 

output/
└── john_smith/                    # slugify(entity) — omitted entirely if no -a entity=
    └── 20260908_124554_18996/     # run_id — fresh per crawl, reused on resume
        ├── pages.jsonl            # raw html + content_hash, one line per stored page
        ├── clean.jsonl            # cleaned_content + tables (+ entity fields)
        ├── blocked.jsonl          # bot-challenge pages that never resolved
        └── summary.json           # fetched/stored/dropped/blocked + reconciliation

10 · Observability

Logging

Every invocation writes its own timestamped file to logs/crawl_<ts>_<pid>.log, in addition to stdout.

Every page that gets fetched-but-discarded logs a line starting Dropped: — duplicate content, empty extraction, entity-irrelevant, non-HTML content type, a non-HTML sitemap entry — so grep "Dropped:" logs/crawl_….log surfaces the full picture in one place. The raw html field never appears in the log; it's redacted to a length placeholder by CrawlerLogFormatter.

11 · Read before relying on this

Known limitations

Heads up

Nothing here is a bug so much as a scope boundary — worth knowing before you hit it.

Frontier isn't entity-scoped

The Redis request queue and URL dupefilter are shared per spider name, not per entity. Two different entity crawls of the same seed.txt back-to-back can collide — run scrapy reset between them.

No 2FA / CAPTCHA in login flows

playwright_login assumes a straight-through submit. A second factor just times out waiting for success_selector and logs as a failed login.

PDFs are skipped, not extracted

Only text/html responses are handled. A PDF (or any other binary) is fetched, logged as Dropped: non-HTML content, and discarded.

robots.txt / sitemap.xml fetch unauthenticated

Discovery requests to those two URLs don't carry auth — usually fine, since they're meant for public search-engine discovery even on gated sites. The pages they list do carry auth.
